THE UNASSISTED HUMAN PROCESS

Fragmented, Blind, and Stale

  • Dirty Excel Spreadsheets: Headers on row 4, banner offsets, stale Part Cards claiming 6 holes when the master record says 4 (like Part 3003).

  • Unit Conversion Traps: Drawing in inches (4.000 in), Excel in mm (101.6 mm). Human fatigue flags false alarms or misses real mismatches.

System Architecture

THE TRI-SOURCE EVIDENCE TRIANGLE

We don't feed raw CAD files or spreadsheets directly to an LLM to guess measurements. The architecture uses deterministic Python engines for mathematical extraction, feeding only verified facts into the language model.

1. Workbooks & Job Cards

Autonomous schema-agnostic extraction. Parses Part No (numeric or text), raw stock size, finished dimensions, machines, cycle times, setup/run minutes, and tools.

ENGINE: Python · OpenPyXL · RapidFuzz Canonical Mapper

2. PDF Drawings & GD&T

Multi-page vector drawing and title-block parser. Extracts nominal dimensions, tolerances (±0.05 mm), material notes, revision tables, and runs OCR fallback for scanned sheets.

ENGINE: PyPDF · PyMuPDF · Vision LLM OCR Fallback

3. 3D CAD B-Rep Geometry

True boundary representation analysis. Calculates exact oriented bounding box (OBB), groups cylindrical surfaces by axis to detect holes vs bosses, and computes solid volume.

ENGINE: OpenCascade Python (`OCP 7.7.2`) · Build123d

HOW WE EXTRACT FACTS WITHOUT GUESSING

A common failure of naive LLM systems is "reading" 3D files as raw text tokens. An IGES file is 5,000 lines of NURBS poles and transformation matrices—LLMs will inevitably hallucinate dimensions.

We solve this with a dual-engine architecture: OpenCascade (the industrial C++ kernel behind FreeCAD) runs natively in Python to perform exact boundary-representation calculus.

// OpenCascade B-Rep Cylindrical Face Extraction
groups = defaultdict(lambda: {"concave": 0, "convex": 0})
